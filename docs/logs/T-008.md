### Langkah verifikasi manual

Perkiraan: satu pemanggilan, sekitar 15–25 detik, sekitar 25 ribu token input (hampir semuanya cache) dan 1–2 ribu token output. Pemanggilan ini memakai kuota langganan.

1. Persiapan:
   - di branch `feat/t-008-stage-2` (`git checkout feat/t-008-stage-2`), lalu `pnpm install`;
   - `.env` **tidak** berisi `CLAUDE_COMMAND`, agar memakai `claude` sungguhan;
   - `claude` sudah login;
   - tidak ada server lain di port 3000.
2. Jalankan `pnpm dev`, lalu buka http://127.0.0.1:3000.
3. Buat proyek: nama bebas (misalnya "Keuangan"), ide `Catatan keuangan pribadi.`, lalu klik **Buat proyek**.
4. Di halaman proyek, klik **Jalankan klarifikasi produk**. Status "Klarifikasi produk sedang berjalan · m:ss" tampil dan waktunya berjalan.
5. Hasil yang harus terlihat setelah selesai:
   - teks "Kejelasan ide N/5: …" dan sejumlah pertanyaan sesuai clarity (clarity 1 → 5, 2 → 4, 3 → 3, 4–5 → 2);
   - setiap pertanyaan punya opsi, **Lainnya**, dan **Lewati, pakai default: …**; pertanyaan bertopik masalah atau pengguna diberi keterangan "(tebakan, ubah bila tidak sesuai)";
   - tidak ada pesan "Gagal: …". Tahap yang tidak lolos validator setelah dua percobaan akan tampil sebagai "Gagal: Output tahap tidak valid…".
6. Jawab sebagian pertanyaan (satu opsi, satu "Lainnya" dengan teks, sisanya lewati), lalu klik **Simpan jawaban**. Yang harus terlihat: "Jawaban tersimpan. Kamu masih bisa mengubahnya." dan "Tahap saat ini" berubah menjadi **Klarifikasi teknis — siap dijalankan**.
7. Opsional: hapus proyek uji lewat tombol **Hapus proyek**.

## Keputusan yang diambil sendiri

1. **Isi prompt mengikuti `buildPrompt` v2** (lebih rinci dan sudah divalidasi 9/9 di `validate-report-v2.json`), bukan versi ringkas `promptStage2` di `e2e-gym.mjs`. Perbedaan dari v2:
   - aturan "Opsi tidak boleh mengandung koma" dihapus (FR-03);
   - ditambah nada "kamu" dan larangan istilah internal dari `COMMON_RULES` `e2e-gym.mjs` (FR-03);
   - daftar topik diisi lewat placeholder `{{topics}}`.
2. **Validator lebih ketat dari rujukan di tiga hal kecil**: `id` pertanyaan harus unik (jawaban merujuk `questionId`), `clarity_reason` wajib, dan opsi tidak boleh kosong. Peringatan koma dari v2 dihapus, sesuai perbaikan FR-03. Kesembilan output nyata tetap lolos.
3. **Peringatan validator tidak disimpan.** `stage_runs` hanya punya `errors_json`, dan peringatan tidak menghentikan tahap.
4. **Bentuk `value` jawaban**: `null` (lewati), string, array, atau `{ lainnya }`. Semua pertanyaan wajib dikirim tepat sekali, dan pertanyaan yang dilewati dikirim `null`, sehingga "melewati" adalah pilihan yang tercatat, bukan kelalaian. "Lainnya" pada pertanyaan multi menggantikan pilihan opsi (tidak digabung).
5. **`projects.current_stage`**: tahap 2 saat menjawab, pindah ke tahap 3 setelah jawaban disimpan. Menjalankan ulang tahap 2 menghapus jawaban lama (pertanyaannya berubah) dan kembali ke tahap 2. Penandaan output tahap sesudahnya tetap di T-016.
6. **Route jalankan tahap dan polling job dibuat di T-008**, karena layar tahap membutuhkannya dan tidak ada task lain yang mencantumkannya. Prasyarat "tahap sebelumnya belum selesai → 409" berupa `notReadyReason` per definisi tahap. Tahap 2 tidak punya prasyarat.
7. **Registry tahap dibuat ulang di setiap `getJobQueue()`**, agar perubahan prompt di `prompts/` langsung terpakai tanpa restart server, walau antreannya bertahan di `globalThis`.
8. **`CLAUDE_COMMAND`** (opsional) untuk menguji UI dengan runner palsu, dan nantinya untuk end-to-end T-017. Tanpa variabel ini, aplikasi memakai `claude`.

## Kendala

- **Bug ditemukan dan diperbaiki: 409 menjadi 500.** Saat diuji di browser, menjalankan tahap ketika job lain masih berjalan menghasilkan 500. `AppError` dilempar oleh `JobQueue` yang dibuat di graf modul `instrumentation.ts`, yang dibundel terpisah dari route, sehingga `instanceof AppError` di `handle()` bernilai salah. Test tidak menangkapnya karena berjalan dalam satu graf modul.
  - Perbaikan: `static [Symbol.hasInstance]` dengan penanda `Symbol.for`, untuk `AppError`, `ClaudeRunError`, dan `StageFailedError`.
  - Test regresi: `test/unit/core/errors.test.ts`, memakai salinan modul lewat import dengan query string.
  - Diverifikasi ulang di browser: 409 dengan pesan yang benar.

- **Kesalahan proses agent:** commit pertama di branch ini (`fce3104`) dibuat dan di-push saat `pnpm check` sebenarnya gagal di typecheck (import dengan query string di `test/unit/core/errors.test.ts`). Exit code-nya tertutup oleh `| tail` di perintah agent. Diperbaiki di commit berikutnya pada branch yang sama, karena riwayat yang sudah di-push tidak diubah. `master` tidak terdampak. Agent sekarang menjalankan `pnpm check` dengan exit code yang diperiksa langsung.

- **Masukan verifikasi manual (putaran 1):** user menjawab pertanyaan dan menyimpan, tetapi tidak melihat "Klarifikasi teknis — siap dijalankan". Database menunjukkan jawaban tersimpan benar (q1 dan q3 `user`, q2 dan q4 `default`; `current_stage` `stage3`). Penyebabnya tampilan: status tahap hanya ada di bagian atas halaman, sedangkan user berada di dekat tombol simpan. Perbaikan: pesan setelah simpan menjadi "Jawaban tersimpan. Tahap berikutnya: Klarifikasi teknis — siap dijalankan." (di samping tombol), dan penanda jawaban tersimpan di bagian tahap 2 juga menyebut tahap berikutnya. Diperiksa test komponen dan uji browser.
