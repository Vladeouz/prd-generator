# T-038 Runner CLI: hapus folder sementara tanpa menimpa hasil atau error

## Status

Selesai. Branch `fix/t-038-hapus-folder-sementara`. Fase 3d.

## Ringkasan

- **Masalah (temuan T-037):** `CliClaudeRunner.run` menghapus folder sementara di `finally` dengan `rmSync`. Di Windows, proses yang baru dimatikan `taskkill` kadang masih memegang folder itu, sehingga `rmSync` melempar `EPERM`. Error dari `finally` menimpa hasil atau `ClaudeRunError` pemanggilan, misalnya `TIMEOUT` menjadi "Terjadi kesalahan tak terduga: EPERM …".
- **Percobaan ulang singkat:** `removeTempDir` memanggil `rmSync` dengan `TEMP_DIR_REMOVE_OPTIONS` (`recursive`, `force`, `maxRetries: 5`, `retryDelay: 100`). Node mencoba ulang `EPERM`/`EBUSY` dengan jeda naik linear (100, 200, … ms; paling lama ±1,5 detik).
- **Gagal hapus hanya dicatat:** `finally` memanggil `cleanup(cwd)`, yang menangkap error hapus dan mencatatnya lewat `logger.warn`, dengan pesan "Folder sementara Claude Code tidak bisa dihapus: `<path>` (`<pesan error>`)". Hasil atau error pemanggilan tidak berubah.
- **Opsi runner baru** (untuk test): `removeDir` (bawaan `removeTempDir`) dan `logger` (bawaan `console`).

## Keputusan yang diambil sendiri

- **Logger berupa opsi `logger: { warn }` dengan bawaan `console`.** Proyek belum punya modul logger (`src/core/` belum memuat logger, padahal disebut di struktur PRD). Membuat modul logger di luar daftar `files`; opsi minimal ini cukup untuk kriteria dan bisa diarahkan ke logger bersama nanti. Usulan untuk `docs/conventions.md`: catatan non-fatal di server memakai `console.warn` sampai ada logger bersama.
- **`maxRetries: 5`, `retryDelay: 100`:** jeda total paling lama ±1,5 detik, singkat untuk pemanggilan yang berlangsung menit-an, dan cukup untuk proses yang dimatikan `taskkill` melepas foldernya. Test `temp-dir.test.ts` juga menjaga agar total jeda di bawah 2 detik.
- **Fungsi hapus disuntikkan lewat opsi `removeDir`**, bukan dengan me-mock `node:fs` di test runner. Cara ini selaras dengan `spawnFn`. Opsi `rmSync` diperiksa di file test tersendiri karena mock `node:fs` berlaku untuk seluruh file.
- **Fungsi hapus palsu di test benar-benar menghapus folder sebelum melempar `EPERM`**, agar test tidak meninggalkan folder di `%TEMP%`.
