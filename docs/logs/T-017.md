## Keputusan yang diambil sendiri

- **Build produksi (`next build` + `next start`), bukan `next dev`.** Lebih dekat ke pemakaian dan tidak bergantung kompilasi per halaman saat test, sehingga lebih stabil untuk syarat 5 run tanpa kegagalan acak. Build hanya ±14 dtk.
- **`.next` bawaan, bukan `distDir` terpisah.** Dicoba `distDir: .next-e2e`, tetapi `next build` lalu menulis ulang `tsconfig.json` (menambah include `.next-e2e/types`). Dengan `.next`, `next build` tidak menghapus `.next/dev`, jadi `pnpm dev` yang sedang berjalan tidak terganggu (diperiksa: isi `.next/dev` tetap ada setelah build). Konsekuensi: hasil `pnpm build` manual sebelumnya tertimpa oleh `pnpm check`.
- **Port 3517**, tetap, tanpa `reuseExistingServer`, agar tidak pernah memakai server dev user (yang memakai database utama).
- **Database dibaca langsung (read-only) di test** hanya untuk yang tidak tampil di layar: dua baris `stage_runs` tahap 3 dan versi dokumen PRD.
- **Penanda placeholder ditulis ulang di `environment.ts`**, tidak diimpor dari `src/projects/export.ts`: transform TypeScript Playwright gagal memuat `src/core/errors.ts` ("Cannot assign to read only property 'Symbol(Symbol.hasInstance)'", static field `AppError`). Bila penanda berubah, export di e2e ditolak (409), jadi test ikut gagal.
- **NFR-02 di e2e**: server produksi berjalan dengan `NODE_ENV=production`, jadi pengaman `NODE_ENV=test` di `CliClaudeRunner` tidak aktif di sana. Sebagai gantinya ada dua lapis: `CLAUDE_COMMAND` palsu dan shim `claude` yang gagal keras di PATH server.
- **Usulan untuk `docs/conventions.md`**: sudah ditambahkan (bagian Test, Claude Code, Database, Script, Versi, Prasyarat).
