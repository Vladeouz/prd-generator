### Langkah verifikasi manual

Perkiraan: satu pemanggilan, sekitar 5–20 detik, sekitar 20–30 ribu token input (hampir semuanya cache system prompt Claude Code) dan di bawah 100 token output. Pemanggilan ini memakai kuota langganan.

1. Persiapan: terminal di `D:\dev\prd-generator`, di branch `feat/t-004-claude-runner` (`git checkout feat/t-004-claude-runner`), `pnpm install` sudah dijalankan. Perintah `claude` sudah login (cek dengan membuka `claude` sekali secara interaktif bila ragu). `.env` dan server tidak dibutuhkan.
2. Jalankan: `pnpm claude:smoke`
3. Hasil yang harus terlihat:
   - `result` berisi `{"ok": true, "pesan": "halo dari Claude Code"}` (atau setara);
   - `token input` dan `token output` berupa angka lebih dari 0, `biaya (USD)` berupa angka, `durasi` dalam detik;
   - baris terakhir `BERHASIL: Claude Code menjawab JSON yang diminta.`, dan exit code 0.
   - Bila muncul `GAGAL [IS_ERROR]` dengan pesan login, jalankan `claude` sekali untuk login lalu ulangi.

## Keputusan yang diambil sendiri

1. **Import relatif berakhiran `.ts`/`.tsx` di seluruh proyek.** Kriteria manual meminta "script yang disediakan task ini" memanggil runner sungguhan. Node 24 bisa menjalankan TypeScript langsung (type stripping), tetapi hanya bila import relatifnya berekstensi. Dengan konvensi ini, `node src/claude/smoke.ts` memakai runner yang sama dengan aplikasi tanpa tsx atau build terpisah. Next.js dan `tsc` tetap berjalan (`allowImportingTsExtensions`, `next build` berhasil). Konsekuensinya: kode di `src/claude/` tidak memakai `enum` atau parameter property. **Usulan:** sudah dicatat di `docs/conventions.md`.
2. **Token input = `input_tokens` + `cache_creation_input_tokens` + `cache_read_input_tokens`**, sama dengan `inputTokensInclCache` di rujukan. `input_tokens` saja bernilai 2 di setiap tahap rujukan, sehingga tidak berguna untuk FR-10.
3. **Perbedaan dari `runClaude` di rujukan:**
   - folder sementara dibuat dan dihapus per pemanggilan, bukan satu folder untuk seluruh run;
   - ada batas waktu, dengan `taskkill /T /F` di Windows (temuan T-002);
   - envelope divalidasi Zod;
   - error bertipe `ClaudeRunError`, bukan objek `{ code, stdout, stderr }`;
   - di Windows `spawn` dipanggil tanpa array argumen, sedangkan rujukan memanggil `spawn(string, { shell: true })` yang setara;
   - `stdin.end(prompt)` sekaligus dengan pengabaian `EPIPE`;
   - percobaan ulang dengan daftar error (`runStage`) tidak di sini, melainkan di T-005.
4. **Pengenalan perintah `claude` sungguhan untuk NFR-02** berdasarkan nama program (`claude`, `claude.cmd/.exe/.ps1/.bat`, termasuk path), sehingga script palsu tetap bisa diuji lewat runner CLI saat `NODE_ENV=test`.
5. **Fixture tahap 2–5 berisi `JSON.stringify(objek, null, 2)`** dari `stage-*.json`, karena teks mentah `result` tidak disimpan di uji rujukan. Fixture `stage6` masih berisi bagian 8 yang ditulis AI. T-012 membangun fixture tanpa bagian 8 sesuai D-05.
6. **`FakeClaudeRunner` memakai antrean respons**, sehingga test bisa menyusun urutan seperti gagal validasi lalu berhasil (T-005, T-017). Antrean yang habis menghasilkan error yang menyebut nomor pemanggilan.
