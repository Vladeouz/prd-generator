# T-023 Runner: model, pengurang overhead, dan streaming

## Status

Selesai. Semua kriteria terbukti, termasuk smoke test **(manual)** dengan `claude` sungguhan yang dijalankan user. Branch `feat/t-023-runner-stream`.

## Ringkasan

- **Bentuk perintah** dari rekomendasi akhir T-022 (`claudeArgs` di `src/claude/cli-runner.ts`):
  - `-p --output-format stream-json --verbose --include-partial-messages --max-turns 1`;
  - `--model <CLAUDE_MODEL>` dan `--effort low`;
  - `--system-prompt "<CLAUDE_SYSTEM_PROMPT>"`, `--tools ""`, `--strict-mcp-config`, `--setting-sources project`, `--disable-slash-commands`, `--no-session-persistence`;
  - Windows: satu string untuk cmd.exe, dengan argumen kosong dan berspasi diberi tanda kutip. Argumen dengan karakter khusus cmd.exe ditolak. Platform lain: array argumen.
- **`CLAUDE_MODEL`**: dibaca dari env lewat `claudeModel()` (`src/core/config/claude.ts`), bawaan `sonnet`, dan ada di `.env.example`. Nilai yang tidak aman untuk string perintah (spasi, `&`, `"`, …) menghasilkan `ClaudeRunError` `INVALID_CONFIG` tanpa menjalankan proses.
- **Stream** (`src/claude/stream.ts`, `StreamReader`):
  - stdout dibaca baris demi baris, termasuk baris yang terpotong di antara potongan stdout;
  - `text_delta` menjadi `onProgress({ kind: 'text', text, chars })`, dan `system/thinking_tokens` menjadi `onProgress({ kind: 'thinking', estimatedTokens })`;
  - `result`, `usage`, dan `total_cost_usd` diambil dari event `result` terakhir lewat `parseEnvelope` yang sudah ada;
  - stream tanpa event `result` menghasilkan `INVALID_ENVELOPE`.
- **`ClaudeRunOptions.onProgress`** dan tipe `ClaudeProgress` dibuat di T-023. `run-stage` belum memakainya; itu bagian T-024.
- **Runner palsu**: `FakeClaudeRunner` mengirim `result` sebagai potongan bertahap (`chunkSize`, `chunkDelayMs`) bila `onProgress` diberikan. Tanpa callback, perilakunya sama seperti sebelumnya.
- **Script palsu** `test/helpers/fake-claude-cli.mjs` kini mengeluarkan format stream: `init`, `thinking_tokens`, potongan `text_delta`, lalu event `result`.
  - Fixture tetap berupa envelope, dan diubah menjadi stream saat dicetak.
  - Opsi baru: `FAKE_CLAUDE_CHUNK_SIZE`, `FAKE_CLAUDE_CHUNK_DELAY_MS`, dan mode `no-result`.
- **`envelopeResult`** juga membaca event `result` terakhir dari stream, sehingga `pnpm claude:smoke` tetap menampilkan pesan error utuh.
- **`pnpm claude:smoke`**:
  - membaca `CLAUDE_MODEL` dari `.env` (variabel proses tetap menang);
  - menampilkan model, jumlah potongan stream, dan waktu potongan pertama;
  - memakai `CliClaudeRunner` dengan perintah baru.

### Langkah verifikasi manual

Perkiraan kurang dari 1 menit dan sekitar $0,003–0,01 kuota. Probe serupa di T-022 memakai 681 token input dan $0,0028.

1. Persiapan:
   - checkout branch: `git checkout feat/t-023-runner-stream`;
   - tidak perlu server;
   - `CLAUDE_MODEL` boleh kosong (bawaan `sonnet`);
   - `.env` tidak wajib untuk smoke.
2. Jalankan:
   ```
   pnpm claude:smoke
   ```
3. Hasil yang harus terlihat:
   - `Perintah: claude, model sonnet …`;
   - `result      : {"ok": true, "pesan": "halo dari Claude Code"}` (atau setara);
   - `token input :` sekitar ratusan sampai ±1.000. Bandingkan dengan ±25.000 sebelum T-023 (T-004);
   - `token output`, `biaya (USD)`, dan `durasi` terisi;
   - `stream      : N potongan teks, pertama di X dtk`, dengan N ≥ 1;
   - `BERHASIL: Claude Code menjawab JSON yang diminta.`
4. Kirim output itu ke agent. Token dan durasinya dicatat di log ini.

## Keputusan yang diambil sendiri

- **Fixture tetap berupa envelope**, dan script palsu mengubahnya menjadi stream saat dicetak. Fixture yang ada (nyata, turunan, sintetis, verifikasi) tidak perlu dibangun ulang, dan `loadClaudeFixture` tetap memakai `parseEnvelope` yang sama dengan event `result`.
- **`--effort low` tetap, tidak lewat env.** D-09 hanya menyebut `CLAUDE_MODEL` sebagai yang bisa diganti.
- **Model divalidasi di runner** (`INVALID_CONFIG`), bukan saat server start, agar server tetap hidup dan pesannya tampil sebagai error job.
- **`rawEnvelope` sekarang berisi baris event `result`**, bukan seluruh stdout. Stream tahap 6 bisa ±2 MB per pemanggilan (T-022), dan field ini tidak disimpan ke database. Bila event `result` rusak, detail error tetap memuat seluruh stdout.
- **`StreamReader` meneruskan `thinking_tokens`**, karena T-022 menemukan fase thinking ±1,5–2 menit tanpa teks. T-024 bisa memakainya sebagai progres.
- **Script spike tidak diubah**: `spikes/claude-efficiency/` tetap sebagai catatan T-022.
