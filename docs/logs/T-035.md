## Keputusan yang diambil sendiri

- **`STAGE_PROFILES` di `src/core/config/claude.ts` sebagai satu sumber pemetaan.** Setiap definisi mengambil profilnya dari sana. Perkiraan (`usage.ts`) dan halaman pengaturan butuh pemetaan tanpa membangun definisi tahap (yang membaca prompt dan template), dan satu tempat mencegah definisi dan pengaturan berbeda. Test memastikan definisi dan `STAGE_PROFILES` sama.
- **Pemeriksaan env di `runStage`, bukan saat job dibuat.** Job tetap dibuat (202) lalu gagal dengan pesan yang menyebut variabelnya, sama seperti template yang tidak valid untuk tahap 6–7. Env dibaca saat tahap dijalankan, jadi tidak perlu disimpan di antrean.
- **Runner tetap punya bawaan (profil `standard`) bila pemanggilan tidak menyebut model dan effort.** Dipakai smoke dan spike. Aplikasi selalu mengirim keduanya dari profil tahap. Nilai bawaannya diambil dari `PROFILE_DEFAULTS`, bukan ditulis di `claudeArgs`.
- **Model dan effort di ringkasan pemakaian diambil dari pemanggilan terakhir tahap itu.** Run lama tanpa model tidak menimpanya. Tahap 7 (7a dan 7b) memakai satu profil, jadi satu nilai cukup.
- **Run sebelum T-035 (model null) tidak ikut perkiraan.** Setelah merge, perkiraan tahap 6–7 kembali ke `TEST_ESTIMATES` sampai ada pemanggilan baru. Ini konsekuensi langsung kriteria "model dan effort yang sama".
- **Log server untuk model `init`** (`console.info` di `runStage`), bukan kolom baru. Kriteria manual meminta model di event `init` dibandingkan dengan pengaturan, sedangkan aplikasi sebelumnya tidak menyimpan atau menampilkan event itu. Log cukup untuk verifikasi tanpa mengubah skema lagi. Usulan untuk `docs/conventions.md` sudah dicatat di bagian Claude Code (`initModel`).
- **CLI palsu menulis `<--model>-palsu` di event `init`**, agar jalur `initModel` teruji dengan proses sungguhan (`cli-runner.int.test.ts`).
