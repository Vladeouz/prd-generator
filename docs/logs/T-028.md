## Ringkasan

- **Data graf** (`src/projects/graph.ts`):
  - `buildGraph` menyusun node dan edge dari data tersimpan, tanpa pemanggilan `claude`: Proyek → Fase → Fitur → Sub-fitur dari `featureDraft` tahap 4. Hanya fitur MVP dan rekomendasi yang diterima yang ikut;

  - setelah 7a: task di bawah fiturnya, dengan jumlah task per fitur dan per fase. Task hapus notes (tanpa fitur) ada di bawah fasenya;
  - rincian task (`files`, *done when*, langkah manual) dari 7b yang berlaku per fase, null bila fasenya belum selesai;
  - posisi deterministik: pohon kiri ke kanan, kolom per kedalaman, satu baris per daun, dan induk di tengah anak pertama dan terakhirnya. Node dicatat induk lebih dulu (urutan Tab mengikuti pohon);
  - `projectGraph({ db }, id)` membaca proyek, tahap 4, 7a, dan 7b. `graphHandlers` untuk route: 200 `{ nodes, edges }`, 404 proyek tidak ada, 409 sebelum tahap 4.
- **Route** `GET /api/projects/{id}/graph` (`src/app/api/projects/[id]/graph/route.ts`).
- **Komponen** (`src/components/feature-graph/`):
  - `FeatureGraph` (klien): React Flow dengan node tidak bisa digeser atau disambung. Kanvas bisa digeser dan di-zoom, kontrol Perbesar/Perkecil/"Pas ke layar", dan `fitView` saat dibuka;
  - `GraphNode`: satu node kustom untuk semua jenis, dengan label jenis, kode, judul, jumlah task, dan garis kiri berwarna token;
  - `NodeDetail`: panel detail (komponen murni) untuk proyek, fase, fitur (deskripsi, sub-fitur, dependensi, jumlah task), sub-fitur, dan task (fase, layer, dependensi, rujukan, file, *done when*, verifikasi manual);
  - pilihan node lewat `onSelectionChange`, sehingga klik dan keyboard (Tab ke node, Enter/Spasi, Escape membatalkan) memakai jalur yang sama. Panel `aria-live="polite"`;
  - label pembaca layar per node (`nodeAriaLabel`) dan teks kontrol React Flow dalam Bahasa Indonesia (`ariaLabelConfig`).
- **Tampilan**: `FeatureGraphSection` di layar tahap 4 (setelah output tahap 4 ada, sebelum daftar non-goals) dan tahap 7 (setelah daftar task 7a ada, sebelum dokumen TASKS). Halaman memanggil `projectGraph` langsung.
- **Warna**: `@xyflow/react/dist/style.css` dipakai, lalu variabel `--xy-*` diganti token di `globals.css`. Di sana juga cincin fokus node (React Flow menghapusnya) dan tombol kontrol 44 px.

### Langkah verifikasi manual

Tidak memakai kuota `claude`: flowchart hanya membaca data yang sudah tersimpan. Perkiraan 5–10 menit.

1. Persiapan: `.env` yang sudah ada (tidak perlu diubah). Pastikan tidak ada `pnpm dev` lain yang berjalan.
2. Di branch ini: `git checkout feat/t-028-flowchart-fitur`, lalu `pnpm install` (paket baru `@xyflow/react`), lalu `pnpm dev`.
3. Buka `http://127.0.0.1:3000/projects/693d7f8a-6571-43aa-994d-329c4bcad462?tahap=7` (proyek "Uji T-012", 7a dan 7b sudah selesai).
   - Bagian "Flowchart fitur" tampil di atas dokumen TASKS. Graf memuat Proyek → 5 fase → fitur → sub-fitur dan task, dan setiap fitur menyebut "N task".
   - Geser kanvas dengan seret, zoom dengan roda mouse atau tombol +/−, lalu tekan tombol "Pas ke layar" (ikon kotak di kanan atas).
   - Klik sebuah task: panel "Detail node" di bawah graf menampilkan file dan *done when*.
   - Tekan Tab sampai fokus masuk ke node (cincin biru terlihat dan graf bergeser ke node itu), lalu Enter: panel berganti. Escape: panel kembali ke petunjuk.
4. Buka `?tahap=4` di proyek yang sama: flowchart tampil di bawah "Fitur MVP per fase".
5. Ganti tema dengan tombol tema di header, lalu ulangi langkah 3 secara singkat. Node, garis, titik latar, dan tombol kontrol harus terbaca di tema terang dan gelap.
6. DevTools (F12) → mode perangkat, lebar 390 px. Graf tetap bisa digeser dengan seret atau sentuh, halaman tidak bergeser ke samping, dan panel detail ada di bawah graf.
7. Hentikan `pnpm dev`.

Yang perlu dikonfirmasi: graf terbaca dan bisa digeser di kedua tema dan di lebar 390 px.

## Keputusan yang diambil sendiri

- **Tata letak pohon kiri ke kanan dihitung di server**, tanpa library layout (dagre/elk). Untuk pohon (setiap node satu induk) cukup satu penelusuran, deterministik, dan bisa di-test tanpa browser.
- **Fitur rekomendasi yang diterima di node kelompok sendiri** ("Fitur rekomendasi yang diterima"), karena belum punya fase di tahap 4. Fase task-nya tetap terlihat di panel detail task.
- **Hanya edge induk–anak.** Dependensi fitur dan task ditampilkan di panel detail sebagai teks, bukan garis. Garis dependensi akan memotong pohon dan membuat graf 37+ task sulit dibaca.
- **Flowchart di layar tahap 4 dan tahap 7**, bukan layar baru. Stepper tetap 8 tahap, dan graf muncul di tempat datanya dibuat.
- **409 untuk graf sebelum tahap 4**, sama dengan pola `PUT …/features` sebelum tahap 4. PRD hanya menyebut respons 200.
- **Node tidak bisa digeser** (`nodesDraggable={false}`). Posisi berasal dari server, dan yang perlu digeser adalah kanvasnya.
- **`minZoom` 0,1**, karena graf proyek dengan puluhan sub-fitur dan task jauh lebih tinggi dari kanvas (fixture gym: 38 sub-fitur dan 42 task). "Pas ke layar" pada zoom terkecil bisa belum memuat seluruh graf; zoom dan geser tetap tersedia.
- **Usulan konvensi** sudah ditambahkan ke `docs/conventions.md` (bagian UI dan desain).
