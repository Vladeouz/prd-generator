# T-040 Test tidak bergantung pada variabel profil Claude dari shell

## Status

Selesai. Branch `test/t-040-isolasi-env-profil`. Fase 3e. Rencana task ditambahkan lebih dulu atas permintaan user di branch `docs/t-040-rencana-isolasi-env` (merge `9f2678f`), termasuk T-040 di `depends_on` T-018.

## Ringkasan

- **Masalah (usulan di log T-038 dan T-039):** shell sesi Claude Code membawa `CLAUDE_EFFORT` (di sesi ini `medium`). `currentEstimateSettings()` tanpa argumen membaca `process.env`, jadi 4 test perkiraan FR-10 di `rerun.int.test.ts` merah, dan `pnpm check` harus dijalankan dengan `env -u`.
- **Unit dan integration test:** `test/helpers/vitest-setup.ts` didaftarkan sebagai `setupFiles` di `vitest.config.ts` dan `vitest.int.config.ts`. File itu memanggil `clearClaudeProfileEnv()` (`test/helpers/claude-profile-env.ts`), yang menghapus `CLAUDE_PROFILE_VARS` dari `process.env` di setiap worker sebelum file test dimuat. Daftar variabelnya diturunkan dari `PROFILE_ENV` di `src/core/config/claude.ts`, jadi tidak ditulis ulang.
- **End-to-end:** `playwright.config.ts` mengisi keempat variabel dengan string kosong di `webServer.env`. Playwright meneruskan `process.env` ke server, lalu nilai di `webServer.env` menimpanya. String kosong berarti bawaan (`claudeProfile`: `env[...]?.trim() || defaults`). Karena variabelnya sudah terdefinisi, `@next/env` juga tidak mengisinya dari `.env`, yang hanya mengisi kunci yang `undefined`. Test yang butuh nilai lain bisa menimpanya setelah baris itu.
- **Bukti di test:**
  - unit test baru di `test/unit/core/config-claude.test.ts`: keempat variabel tidak ada di `process.env`, dan `claudeProfile()` tanpa env mengembalikan `PROFILE_DEFAULTS`;
  - `test/e2e/full-flow.spec.ts` sekarang memeriksa `stage_runs.model`/`effort` tahap 6 (`standard`) dan review kedua (`reasoning`) sama dengan `PROFILE_DEFAULTS`.
- Test yang menguji nilai env (`config-claude.test.ts`, `profiles.int.test.ts`, `template.int.test.ts`, `smoke.int.test.ts`) tidak diubah. Semuanya sudah memberi env eksplisit, dan `smoke.int.test.ts` menimpa env proses anak setelah `...process.env`.
- `src/` tidak berubah: aplikasi tetap membaca keempat variabel dari env dan `.env`.

## Keputusan yang diambil sendiri

- **Daftar variabel dan setup dipisah ke dua file.** `claude-profile-env.ts` tanpa efek samping, sehingga bisa diimpor `playwright.config.ts` dan unit test. `vitest-setup.ts` hanya memanggilnya. Daftar diturunkan dari `PROFILE_ENV`, sehingga profil baru otomatis ikut terhapus.
- **E2e memakai string kosong, bukan `delete process.env[...]` di config.** String kosong juga memblokir nilai dari `.env` repo saat `next build`/`next start`, tidak hanya nilai dari shell. Nilainya juga terlihat di satu tempat bersama env server lainnya. `playwright.config.ts` mengimpor `src/core/config/claude.ts` lewat helper, dan modul itu tanpa class, jadi aman untuk transform Playwright.
- **Assertion e2e ditambahkan** (di luar kalimat kriteria, tetapi di dalam "test terkait"), agar kriteria "server e2e tidak mewarisi" punya test yang gagal bila aturannya dilepas.
