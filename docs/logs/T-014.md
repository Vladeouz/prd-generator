### Penyebab

Kedua penolakan berasal dari validator, bukan dari kualitas output. Diuji ulang dengan validator yang sama pada output mentah kedua percobaan (script di luar repo, PRD versi 2 sebagai acuan):

- percobaan 1 hanya punya 1 error (aturan Flutter web);
- percobaan 2 hanya punya 8 error (*done when* multi-baris);
- tidak ada error jenis lain.

1. **Aturan Flutter web terlalu ketat** (interpretasi yang sudah ditandai di Keputusan).
   - Percobaan 1, T-081 "Uji kinerja API dengan data besar" (layer `test`): langkah manualnya benar dan lengkap (`.env`, `docker compose up -d --wait`, migrasi, `perf:seed`, `perf:measure`), tetapi ditolak karena tidak ada perintah Flutter web. Task itu memang tidak memakai Flutter.
2. **Parser hanya membaca baris pertama *done when*.**
   - Pada percobaan 2, Claude menulis *done when* sebagai beberapa baris: baris `done when:` diikuti sub-butir, lalu paragraf yang diakhiri `pnpm check` hijau, dan pada task manual diikuti langkah bernomor. Ini sesuai prompt ("langkahnya ditulis lengkap di baris-baris berindentasi di bawah done when").
   - `parseTasks` mengambil *done when* hanya sampai akhir baris pertama (misalnya "migrasi sudah di-commit dengan semua constraint PRD:"), jadi akhiran `pnpm check` hijau tidak terlihat.
   - Fixture turunan dan test hanya memakai *done when* satu baris, jadi bug ini tidak tertangkap.
3. **Layar tidak menunjukkan percobaan ulang.** Selama ±15 menit layar hanya menampilkan "sedang berjalan", sehingga user tidak bisa membedakan job yang macet dari job yang sedang mencoba ulang.

### Usulan perbaikan (menunggu persetujuan user)

1. *Done when* dibaca dari baris `done when:` sampai akhir blok task. Langkah manual bernomor (`1.`, `2.`, …) tidak dihitung, dan baris kriteria terakhir harus diakhiri `pnpm check` hijau. Ini perbaikan bug, bukan perubahan kriteria. Output percobaan 2 dijadikan fixture regresi.
2. Perintah Flutter web hanya wajib untuk task manual layer `app`, atau task manual yang menyebut Flutter atau layar. `.env`, `docker compose up`, dan flag incognito pada setiap `flutter run -d chrome` tetap wajib. Ini mengubah interpretasi kriteria FR-08, jadi butuh persetujuan.
3. Layar tahap yang sedang berjalan menampilkan nomor percobaan dan alasan penolakan percobaan sebelumnya.
4. Perkiraan durasi tahap 7 dinaikkan dari "sekitar 3 menit" menjadi "sekitar 5–15 menit (bisa dua kali bila output dicoba ulang)".

- **Daftar setup template di prompt** diambil dari `docs/conventions.md` di repo template (dibaca saat task ini). Validator hanya menolak lima hal yang disebut FR-08. Kerangka API dan Flutter, auth, dan CI hanya dilarang lewat prompt, karena judul task fitur sering menyebut kata yang sama.

- **Batas minimal 10 task diganti "minimal satu task"**, karena proyek kecil tanpa task setup bisa punya kurang dari 10 task. Setiap FR tetap wajib dirujuk.
- **Interpretasi kriteria manual FR-08**: setiap task **(manual)** wajib menyebut `.env`, `docker compose up`, dan perintah Flutter web, dan setiap `flutter run -d chrome` di task mana pun wajib memakai `--web-browser-flag=--incognito`. Akibatnya, task manual yang hanya menguji API juga wajib menyebut perintah Flutter web. Perlu dikonfirmasi user bila task seperti itu dianggap wajar.
- **`refs: -` diizinkan** (misalnya task hapus notes), tetapi baris `refs:` wajib ada.
- **Layer `docs` ditambahkan** ke daftar layer rujukan, untuk task dokumentasi.
- **Metadata task** adalah semua baris berindentasi di bawah judulnya, sehingga langkah manual bernomor ikut terbaca. *Done when* dibaca sampai akhir baris.
