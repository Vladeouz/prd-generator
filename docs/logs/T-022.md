## Ringkasan

- **Flag diverifikasi** dari `claude --help` Claude Code 2.1.302 (tabel di bawah).
- **`spikes/claude-efficiency/prompts.mjs`** menyusun prompt dari proyek "Uji T-012" (`693d7f8a-…`) memakai `stage2Definition` dan `stage6Definition` dari `src/` apa adanya:
  - database utama disalin dulu ke folder sementara lewat `better-sqlite3` `backup`, karena `buildPrompt` tahap 6 mencatat commit template;
  - prompt D: konvensi utuh diganti bagian terpilih (`selectSections`, sub-heading ikut), dan dua kalimat prompt diganti agar PRD merujuk konvensi tanpa menyalinnya. `prompts/stage-6.md` tidak diubah.
- **`spikes/claude-efficiency/run.mjs`** menjalankan 12 pemanggilan, masing-masing di folder sementara kosong dengan prompt lewat stdin, dan bentuk perintah Windows/non-Windows sama dengan runner CLI:
  - 5 probe dengan prompt kecil (`Berapa 37 x 43?`): untuk menentukan cara mematikan thinking, dan untuk mengukur overhead sebelum dan sesudah pengurang;
  - tahap 2 dengan A, B, C;
  - tahap 6 dengan D, C, B, A. A paling akhir karena paling lama.
- **Yang dicatat per pemanggilan**:
  - token input (baru, cache tulis, cache baca), token output, `total_cost_usd`, durasi, ukuran output, dan karakter per token output;
  - blok dan karakter thinking dari event stream;
  - waktu teks pertama, dan apakah event `result` berisi `usage` dan `total_cost_usd`;
  - `model`, `tools`, `mcp_servers` dari event `init`;
  - hasil validator yang ada (`validateStage2`, `validatePrd`);
  - jumlah baris konvensi yang tersalin persis ke PRD.
- **Hasil** ditulis ke `spikes/claude-efficiency/results/`: `summary.md`, `results.json`, output per run, dan prompt. Raw stream `*.ndjson` di-ignore.
- **Pengaman kuota**: bila satu probe gagal (misalnya flag ditolak), script berhenti sebelum tahap 2 dan 6.

### Flag dari `claude --help` (2.1.302)

| Kebutuhan | Flag | Catatan |
| --- | --- | --- |
| Model | `--model <model>` | Alias `sonnet`, `opus`, `fable`, atau nama lengkap |
| Mematikan extended thinking | **Tidak ada flag** | `--effort <level>` hanya mengatur tingkat usaha. Dicoba dua cara: env `MAX_THINKING_TOKENS=0` (probe `probe-env`) dan `--settings <file>` berisi `{"alwaysThinkingEnabled": false}` (probe `probe-settings`). Keduanya dibandingkan dengan `probe-sonnet` lewat blok thinking di stream |
| System prompt sendiri | `--system-prompt <prompt>` | `--append-system-prompt` hanya menambah. Teks pendek tanpa karakter khusus cmd.exe, jadi aman di string perintah Windows |
| Tanpa tool | `--tools ""` | Dibuktikan dari `tools` di event `init` |
| Tanpa server MCP | `--strict-mcp-config` (tanpa `--mcp-config`) | Dibuktikan dari `mcp_servers` di event `init` |
| Tanpa pengaturan user | `--setting-sources project` | Folder kerja sementara kosong, jadi pengaturan project/local tidak ada. `--settings` tetap berlaku |
| Pengurang lain | `--disable-slash-commands`, `--no-session-persistence`, `--safe-mode` | `--safe-mode` mematikan CLAUDE.md user, plugin, hook, dan skill, dengan auth tetap normal. Dampaknya diukur `probe-C-tanpa-safe-mode` vs `probe-C` |
| Stream | `--output-format stream-json` + `--verbose` + `--include-partial-messages` | Tanpa `--include-partial-messages`, dengan `--max-turns 1` hanya ada satu pesan utuh di akhir, jadi tidak ada potongan teks |
| Tidak dipakai | `--bare` | Auth hanya `ANTHROPIC_API_KEY`/`apiKeyHelper` (OAuth tidak dibaca). Tidak cocok dengan langganan (PRD bagian 1) |
| Tidak dipakai | `--exclude-dynamic-system-prompt-sections` | Diabaikan bila `--system-prompt` dipakai |

`--max-turns` tidak tercantum di `--help` 2.1.302, tetapi sudah dipakai runner dan terbukti di T-004 dan T-012.

### Konfigurasi

- **A**: `claude -p --output-format json --max-turns 1`.
- **B**: A + `--model sonnet` + thinking mati (env dan `--settings` sekaligus; probe menentukan mana yang cukup).
- **C**: B dengan:
  - `--output-format stream-json --verbose --include-partial-messages`;
  - `--system-prompt "…"`, `--tools ""`, `--strict-mcp-config`, `--setting-sources project`;
  - `--disable-slash-commands`, `--no-session-persistence`, `--safe-mode`.
- **D**: C + bagian konvensi terpilih. Hanya untuk tahap 6; prompt tahap 2 tidak berisi konvensi, jadi D tahap 2 sama dengan C.

Bagian konvensi tahap 6 di D (24.186 dari 76.495 karakter): Struktur repo, Job (pg-boss), Autentikasi, Port push dan storage, Pagination, Database, Format error, Clean Architecture API (beserta sub-heading Pola lanjutan API, Aturan bisnis, Organisasi dan tenancy). Ukuran prompt: tahap 2 2.546, tahap 6 104.048, tahap 6 D 52.108 karakter.

### Langkah verifikasi manual

Perkiraan: 30–45 menit dan sekitar $3–5 kuota. Sebagian besar dari `s6-A` (±9 menit, ±$1,7 di T-012).

1. Persiapan:
   - `.env` berisi `TEMPLATE_DIR` yang menunjuk salinan lokal `profil-a-template`;
   - `CLAUDE_COMMAND` tidak perlu dan tidak dipakai script;
   - `data/prd-generator.db` masih berisi proyek "Uji T-012". Database hanya dibaca dan disalin;
   - server `pnpm dev` boleh berjalan atau tidak.
2. Dari root repo, cek tanpa kuota:
   ```
   git checkout chore/t-022-spike-efisiensi-claude
   node spikes/claude-efficiency/run.mjs --dry-run
   ```
   Harus tampil 12 perintah, serta prompt `stage2` 2546, `stage6` 104048, dan `stage6Selected` 52108 karakter.
3. Jalankan:
   ```
   node spikes/claude-efficiency/run.mjs
   ```
   - Setiap baris `[i/12]` harus diakhiri durasi, token, dan biaya.
   - Bila probe gagal, script berhenti sendiri; kirim outputnya.
   - Bila ada run yang gagal atau terputus, ulangi hanya run itu dengan `--only <id>` (misalnya `--only s6-A`). Hasil lain tetap tersimpan.
4. Selesai bila tampil `Selesai, 0 gagal`. Beri tahu agent; agent membaca `spikes/claude-efficiency/results/summary.md` dan `results.json`, lalu melengkapi log ini.

## Keputusan yang diambil sendiri

- **Probe kecil sebelum run besar.** Tidak ada flag thinking di `--help`, jadi cara mematikannya harus dibuktikan. Probe juga mengukur overhead per pengurang dengan biaya kecil. Bila salah satu flag ditolak, kuota untuk run besar tidak terpakai.
- **B memakai `json` dan C/D memakai `stream-json`.** Dengan begitu B mengisolasi efek model dan thinking terhadap A, dan stream dibuktikan di C/D. Thinking di B dibuktikan lewat probe dengan flag yang sama dan lewat karakter per token output.
- **Tahap 2 tidak dijalankan dengan D**, karena perintah dan promptnya identik dengan C. Ini menghemat satu pemanggilan.
- **Salinan database lewat `backup`**, bukan membuka database utama, agar tidak ada penulisan (`template_commit`) ke data user.
- **Database tidak dibuka ulang untuk validasi**: validator dipanggil langsung pada `result`, sama dengan `parse` + `validate` di definisi tahap.
