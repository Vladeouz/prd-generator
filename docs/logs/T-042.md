## Keputusan yang diambil sendiri

- **Seluruh API Contract, bukan baris per fase.** Pemetaan lewat path yang disebut blok FR dan judul task sempat diimplementasikan dan diukur. Fase 0–2 mendapat baris yang benar, tetapi fase 3 hanya 4 baris (confirm, reject, dan payment admin hilang) dan fase 4 hanya 2 baris (`notifications/{id}/read` dan kedua endpoint `device-tokens` hilang), karena FR-08 dan FR-11 menyebut aksinya dengan kata, bukan path. Kriteria mengizinkan seluruh tabel untuk kasus ini. Pemetaan per fase juga membuat isi prompt berbeda antarfase.
- **API Contract diletakkan di awalan prompt (placeholder `{{apiContract}}`), bukan di dalam `prdExcerpt`.** Kriteria menyebut "cuplikan PRD untuk 7b (`prd-excerpt.ts`)". Fungsinya tetap di `prd-excerpt.ts`, tetapi dirender terpisah. Isinya sama untuk semua fase, jadi bila diletakkan di bagian khusus fase, tambahan 6 rb karakter itu tidak ikut cache di empat fase lainnya.
- **Catatan pertentangan di `file_notes`, bukan field baru.** Format output 7b dan `docs/TASKS.md` tidak perlu berubah, dan catatan tampil di samping file yang terkait.
- **Tidak ada validator baru untuk "field di luar kontrak"** (kriteria tidak memintanya). Field body ditulis bebas dalam kalimat, sehingga deteksi otomatis berisiko salah. Efeknya diverifikasi di T-043 dengan menjalankan ulang tahap 7 sungguhan.
