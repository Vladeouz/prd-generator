## Kendala

- **`pnpm check` pertama gagal di dua langkah:**
  - Biome: format satu baris di helper test, dirapikan dengan `biome check --write`. Output Biome sempat terpotong, lalu dibaca utuh lewat `rtk proxy`;
  - end-to-end: `next build` berhenti dengan `SecurityFatalError` dari CLI Next.js 16.4.0 (peringatan kerentanan keamanan yang sama seperti di T-036), bukan test yang gagal. Perintah upgrade di pesan itu tidak dijalankan.

  `pnpm check` diulang dari awal: hijau.
- **Setelah log ditulis dan task dicentang, `pnpm check` diulang sampai hijau di run ketiga:**
  - dua run gagal di end-to-end karena `SecurityFatalError` yang sama. Pesannya muncul berselang-seling, kira-kira setiap run `next build` yang kedua;
  - satu run gagal di integration test `cli-runner.int.test.ts` › "melewati batas waktu → TIMEOUT …" dengan `EPERM` saat runner menghapus folder sementara (lihat temuan di bawah).
- **Temuan di luar task (usulan task), runner CLI di Windows:**
  - Saat batas waktu tercapai, `CliClaudeRunner` mematikan proses (`taskkill`) lalu langsung menghapus folder sementara di `finally` (`rmSync(cwd, …)`, `src/claude/cli-runner.ts`).
  - Proses yang baru dimatikan kadang masih memegang folder itu, sehingga `rmSync` melempar `EPERM` dan menimpa `ClaudeRunError` `TIMEOUT`. Di aplikasi, job yang melewati batas waktu bisa gagal dengan pesan "Terjadi kesalahan tak terduga: EPERM …", bukan pesan batas waktu.
  - Kemungkinan ini juga kegagalan sekali yang penyebabnya belum diketahui di T-035.
  - Usulan: penghapusan folder sementara tidak boleh menimpa hasil atau error pemanggilan (abaikan error hapus, atau coba ulang dengan `maxRetries`), dengan unit test `spawnFn` palsu yang membuat penghapusan gagal.
- **Usulan task lain:** peringatan keamanan Next.js 16.4.0 dari CLI kini menghentikan `next build` secara berselang-seling, sehingga `pnpm check` bisa gagal tanpa ada test yang gagal. Perlu diputuskan user (upgrade Next.js sebagai task tersendiri).
